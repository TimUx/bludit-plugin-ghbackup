# Bludit GitHub Backup

Bludit 3.x plugin for versioned backups of `bl-content`, `bl-plugins` and `bl-themes` to a GitHub repository via the GitHub REST API.

## Features

- No Git, SSH, Composer or shell access required on the Bludit server.
- Manual backups from the Bludit admin area.
- Optional visitor/admin scheduler for shared hosting without cron.
- Optional **GitHub Actions scheduler** managed automatically by the plugin.
- Protected HTTP scheduler for GitHub Actions, KUMA, UptimeRobot, cron-job.org, curl, wget and other HTTP clients.
- Configurable backup intervals.
- Automatically creates or updates `.github/workflows/bludit-ghbackup.yml` when GitHub Actions are enabled.
- Stores the scheduler token as the GitHub Actions repository secret `GHBACKUP_SCHEDULER_TOKEN`, never in the workflow source.
- Deleted local files are also removed from the backup tree.
- Cache, session, temp and log directories are excluded.
- Maximum individual file size: 50 MiB.

## Installation

1. Copy the `ghbackup` directory to `bl-plugins/`.
2. In Bludit, open **Plugins** and activate **GitHub Backup**.
3. Create a GitHub repository for the backups.
4. Create a **Fine-grained Personal Access Token** and grant the permissions described below.
5. Enter the GitHub owner, repository and branch in the plugin.
6. Select the Bludit directories to back up.
7. Use **Test GitHub connection**.
8. Use **Backup now** for the first manual backup.
9. Optionally enable a scheduler.

## GitHub token for normal backups

In GitHub, open:

**Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

Recommended settings:

- **Repository access:** Only selected repositories → select the backup repository.
- **Repository permissions:** **Contents → Read and write**.

The token is stored in the plugin settings and used by PHP for GitHub API access.

## GitHub Actions scheduler

The GitHub Actions scheduler is optional.

When **GitHub Actions** is enabled and the settings are saved, the plugin automatically:

1. Generates a random scheduler token if none exists.
2. Reads the repository's GitHub Actions public key.
3. Encrypts the scheduler token with LibSodium.
4. Creates or updates the repository secret `GHBACKUP_SCHEDULER_TOKEN`.
5. Creates or updates `.github/workflows/bludit-ghbackup.yml`.
6. Applies the configured schedule.
7. Keeps `workflow_dispatch` available for manual runs.

### Additional token permissions

For automatic workflow and secret management, the Fine-grained token needs:

- **Contents → Read and write**
- **Workflows → Read and write**
- **Secrets → Read and write**

A token with only **Contents** may be sufficient for normal manual backups, but automatic GitHub Actions and secret management can fail.

### Changing the interval

The selected interval is written into the generated workflow as a GitHub Actions cron schedule.

The workflow is always maintained on the repository's **default branch**, because scheduled GitHub Actions workflows run from the default branch. The actual backup can still target the separate backup branch configured in the plugin.

Available intervals:

| Plugin setting | Schedule |
|---|---|
| Every hour | hourly |
| Every 6 hours | every 6 hours |
| Every 12 hours | every 12 hours |
| Daily | daily |
| Weekly | weekly |

GitHub Actions does not guarantee execution at the exact second specified. Scheduled runs may be delayed during periods of high load.

### Disabling GitHub Actions

If **GitHub Actions** is disabled and the settings are saved:

- the scheduled trigger is removed from the generated workflow;
- `workflow_dispatch` remains available;
- the workflow file is not deleted;
- the repository secret is retained.

## HTTP scheduler

The plugin exposes a protected HTTP trigger:

```
https://example.com/?ghbackup_scheduler=1
```

The recommended authentication method is the HTTP header:

```
X-GHBackup-Token: <scheduler-token>
```

Example with curl:

```bash
curl --fail --silent --show-error \
  -H "X-GHBackup-Token: YOUR_SCHEDULER_TOKEN" \
  "https://example.com/?ghbackup_scheduler=1"
```

The endpoint returns JSON and a suitable HTTP status code.

It can be used with:

- KUMA
- UptimeRobot
- cron-job.org
- Zabbix
- Nagios-compatible HTTP checks
- NAS systems
- Raspberry Pi
- Windows PowerShell
- curl/wget
- GitHub Actions

The scheduler token is generated by the plugin and is independent of the GitHub Personal Access Token.

## GitHub Actions workflow

The generated workflow does **not** contain the scheduler token. It reads the repository secret:

```yaml
env:
  GHBACKUP_TOKEN: ${{ secrets.GHBACKUP_SCHEDULER_TOKEN }}
```

It then calls the Bludit HTTP endpoint with:

```text
X-GHBackup-Token: <secret>
```

This keeps the secret out of the workflow source and repository history.

## Scheduling without GitHub Actions

On shared hosting without cron, the normal automatic scheduler can also run on public page requests.

This means:

- no cron is required;
- a visitor can trigger a due backup;
- an admin request can also trigger a due backup;
- exact wall-clock execution cannot be guaranteed without an external trigger.

For sites with little or no traffic, GitHub Actions or another external HTTP monitor is recommended.

## Security

- Always use HTTPS for the HTTP scheduler endpoint.
- Never publish the scheduler token.
- Prefer the HTTP header instead of a query-string token.
- Restrict the GitHub Personal Access Token to the backup repository.
- Never commit tokens to the repository.
- Rotate a token immediately if it is exposed.

## Troubleshooting

### GitHub Actions setup fails

Check the Fine-grained token permissions:

- Contents: Read and write
- Workflows: Read and write
- Secrets: Read and write

Also verify that the token is restricted to the correct repository.

### Workflow exists but scheduled runs do not start

Open **GitHub → Actions → Bludit GitHub Backup** and verify that the workflow is enabled.

Use **Run workflow** to test it manually.

The configured website must also be publicly reachable over HTTPS from GitHub-hosted runners.

### HTTP scheduler returns 401

The scheduler token is missing or incorrect.

Send the plugin-generated token as:

```text
X-GHBackup-Token: YOUR_SCHEDULER_TOKEN
```

### HTTP scheduler returns 503

The GitHub Actions scheduler is disabled or the GitHub repository configuration is incomplete.

Enable **GitHub Actions** and save the plugin configuration again.

## Backup structure

By default, files are stored below:

```
bludit-backup/
├── bl-content/
├── bl-plugins/
└── bl-themes/
```

The prefix can be changed in the plugin configuration.

## Compatibility

- Bludit 3.22+
- PHP versions supported by the installed Bludit version
- PHP cURL extension
- PHP Sodium extension for GitHub Actions secret management
