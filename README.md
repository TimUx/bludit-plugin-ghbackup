# Bludit GitHub Backup

Bludit 3.x plugin for versioned backups of `bl-content`, `bl-plugins` and `bl-themes` to a GitHub repository via the GitHub REST API.

## Features

- No Git, SSH, Composer or shell access required on the Bludit server.
- Manual backup from the Bludit admin area.
- Optional visitor/admin scheduler for shared hosting without cron.
- Optional **GitHub Actions scheduler** managed automatically by the plugin.
- Generic protected HTTP scheduler for GitHub Actions, KUMA, UptimeRobot, cron-job.org, curl, wget and other HTTP clients.
- Configurable backup interval.
- The plugin creates or updates `.github/workflows/bludit-ghbackup.yml` automatically when GitHub Actions is enabled.
- The scheduler token is stored as the GitHub Actions repository secret `GHBACKUP_SCHEDULER_TOKEN`, not in the workflow YAML.
- Deleted local files are removed from the backup tree.
- Cache/session/temp/log directories are excluded.
- Maximum individual file size: 50 MiB.

## Installation

1. Copy the `ghbackup` directory to `bl-plugins/`.
2. In Bludit, open **Plugins** and activate **GitHub Backup**.
3. Create a GitHub repository for the backup.
4. Create a GitHub **Fine-grained Personal Access Token** and configure the permissions described below.
5. Enter the GitHub owner, repository and branch in the plugin.
6. Select which Bludit directories should be backed up.
7. Use **Test GitHub connection**.
8. Use **Backup now** for the first manual backup.
9. Optionally enable a scheduler.

## GitHub token for normal backups

Create a **Fine-grained Personal Access Token** at GitHub:

**GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

Recommended settings:

- **Repository access:** Only selected repositories → select the backup repository.
- **Repository permissions:** **Contents → Read and write**.

This token is stored in the Bludit plugin settings and is used by PHP to access the GitHub API.

## GitHub Actions scheduler

The GitHub Actions scheduler is optional.

When **GitHub Actions verwenden** is enabled and the settings are saved, the plugin automatically:

1. Generates a random scheduler token if none exists.
2. Reads the repository's GitHub Actions public key.
3. Encrypts the scheduler token with LibSodium.
4. Creates/updates the repository secret `GHBACKUP_SCHEDULER_TOKEN`.
5. Creates or updates `.github/workflows/bludit-ghbackup.yml`.
6. Sets the configured schedule.
7. Keeps `workflow_dispatch` enabled for manual runs.

### Additional token permissions

For automatic workflow/secret management, the Fine-grained token also needs:

- **Contents → Read and write**
- **Workflows → Read and write**
- **Secrets → Read and write**

GitHub documents that modifying files below `.github/workflows/` requires the Workflows repository permission in addition to Contents, and repository Actions secrets require the Secrets repository permission.

If the token only has Contents permission, normal manual backups can work but automatic GitHub Actions setup will fail.

### Changing the interval

The selected interval is written into the generated workflow as a GitHub Actions cron schedule. The workflow itself is always maintained on the repository's default branch, because GitHub scheduled workflows run only from the default branch. The actual backup can still target the separate branch configured in the plugin.

When the interval is changed and the plugin settings are saved, the workflow file is updated automatically.

Available intervals:

| Plugin setting | Schedule |
|---|---|
| Every hour | hourly |
| Every 6 hours | every 6 hours |
| Every 12 hours | every 12 hours |
| Daily | daily |
| Weekly | weekly |

GitHub Actions schedules are not guaranteed to start at the exact second specified; GitHub can delay scheduled runs during periods of high load.

### Disabling GitHub Actions

If **GitHub Actions verwenden** is disabled and the settings are saved:

- the scheduled trigger is removed from the generated workflow;
- `workflow_dispatch` remains available;
- the workflow file itself is not deleted;
- the repository secret is retained.

This avoids accidentally destroying a manually useful workflow.

## Generic HTTP scheduler

The plugin exposes a protected HTTP trigger:

```
https://example.com/?ghbackup_scheduler=1
```

The recommended authentication method is the HTTP header:

```
X-GHBackup-Token: <scheduler-token>
```

Example with curl:

```bash
curl --fail --silent --show-error \
  -H "X-GHBackup-Token: YOUR_SCHEDULER_TOKEN" \
  "https://example.com/?ghbackup_scheduler=1"
```

The endpoint returns JSON and an HTTP status code suitable for monitoring systems.

The same endpoint can be used by:

- KUMA
- UptimeRobot
- cron-job.org
- Zabbix
- Nagios-compatible HTTP checks
- NAS systems
- Raspberry Pi scripts
- Windows PowerShell
- curl/wget
- GitHub Actions

The scheduler token is generated by the plugin and is independent of the GitHub Personal Access Token.

## GitHub Actions workflow

The generated workflow does **not** contain the scheduler token. It reads the repository secret:

```yaml
env:
  GHBACKUP_TOKEN: ${{ secrets.GHBACKUP_SCHEDULER_TOKEN }}
```

It then calls the Bludit HTTP endpoint with:

```text
X-GHBackup-Token: <secret>
```

This keeps the secret out of the repository history and workflow source.

## Scheduling without GitHub Actions

For shared hosting without cron, the plugin can also execute the existing automatic scheduler on normal public/admin requests.

This means:

- no cron is required;
- a visitor can trigger a due backup;
- the admin area can also trigger a due backup;
- exact wall-clock execution cannot be guaranteed without an external trigger.

For sites with little or no traffic, GitHub Actions or another external HTTP monitor is recommended.

## Security notes

- Use HTTPS for the public HTTP scheduler endpoint.
- Never publish the scheduler token.
- Prefer the HTTP header over a query-string token so the secret is less likely to appear in access logs and browser history.
- Restrict the GitHub Personal Access Token to the backup repository.
- Do not commit the GitHub Personal Access Token or scheduler token into the repository.
- Rotate either token if it is exposed.

## Troubleshooting

### GitHub Actions setup fails

Check the Fine-grained token permissions:

- Contents: Read and write
- Workflows: Read and write
- Secrets: Read and write

Also check that the token is restricted to the correct repository.

### Workflow exists but scheduled runs do not start

Open **GitHub → Actions → Bludit GitHub Backup** and check whether the workflow is enabled.

Use **Run workflow** to test it manually.

Also verify that the configured website URL is publicly reachable over HTTPS from GitHub-hosted runners.

### HTTP scheduler returns 401

The scheduler token is missing or incorrect.

Use the token generated/configured by the plugin and send it as:

```text
X-GHBackup-Token: YOUR_SCHEDULER_TOKEN
```

### HTTP scheduler returns 503

GitHub Actions scheduler is disabled or the GitHub repository configuration is incomplete.

Enable **GitHub Actions verwenden** and save the plugin configuration again.

## Backup structure

By default, files are stored below:

```
bludit-backup/
├── bl-content/
├── bl-plugins/
└── bl-themes/
```

The prefix can be changed in the plugin configuration.

## Compatibility

- Bludit 3.22+
- PHP versions supported by the installed Bludit version
- PHP cURL extension
- PHP Sodium extension when GitHub Actions secret management is enabled
